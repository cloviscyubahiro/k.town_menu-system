Go live

Connect guests’ phones, the kitchen, reception and the owner’s phone, anywhere. Free, about 30 minutes, no credit card.

How it works

The system you have is a website. In demo mode it keeps its data inside one browser. In live mode it keeps the data in Firebase, Google’s free database for apps, so every device sees the same orders within a second. Firebase also keeps working when the connection drops for a moment and catches up when it comes back.

You need: a Google account, the K.Town folder, and the owner’s email address. If you plan a web address of your own (for example menu.ktown.rw), set it up before printing the QR cards, so you only print once.

1

Create the Firebase project

  1. Go to console.firebase.google.com and sign in with Google.
  2. Create a project, name it ktown-karongi (any name works). Google Analytics is not needed: switch it off.
2

Create the database

  1. In the left menu: Build → Firestore Database → Create database.
  2. Keep the database ID as (default). Only the default database is free.
  3. Choose a location close to Rwanda, for example africa-south1 (Johannesburg) or europe-west1 (Belgium). It cannot be changed later.
  4. Start in production mode, then Create.
3

Turn on sign-in

  1. Build → Authentication → Get started.
  2. Under Sign-in method, enable Anonymous (guests, no sign-up needed) and Email/Password (staff).
4

Create the staff accounts

  1. Authentication → Users → Add user.
  2. Add the owner’s email and a password. Then, if you like, one account for reception and one for the kitchen (any email addresses you control, for example ktown.kitchen@gmail.com).
5

Add the security rules

  1. Open firestore.rules from the K.Town folder in Notepad or VS Code.
  2. Replace owner@example.com with the owner’s email, in lowercase. Keep the quotes.
  3. Copy the whole file. In Firebase: Firestore Database → Rules, paste over everything, press Publish.

The rules make sure guests can only order, book, call staff and send feedback, that only staff see orders, and that only the owner can change the menu, prices, tables and settings.

6

Connect the K.Town system to Firebase

  1. Click the gear icon, Project settings → General. Under Your apps press the web icon </>, name it K.Town, press Register app.
  2. Firebase shows a firebaseConfig block. Open firebase-config.js in the K.Town folder and replace the line window.KT_FIREBASE_CONFIG = null; with your values:
window.KT_FIREBASE_CONFIG = {
  apiKey: "AIzaSy...",
  authDomain: "ktown-karongi.firebaseapp.com",
  projectId: "ktown-karongi",
  storageBucket: "ktown-karongi.firebasestorage.app",
  messagingSenderId: "123456789012",
  appId: "1:123456789012:web:abc123"
};

These values are not secret: they only say which project to talk to. The security rules from step 5 protect the data.

7

Put the system online

Pick one. Both are free and give you an https address that works on every phone.

Easiest: Netlify Drop

  1. Go to app.netlify.com/drop.
  2. Drag the whole K.Town folder onto the page.
  3. Create a free account to keep the site online, then rename the site, for example ktown-karongi, so the address is https://ktown-karongi.netlify.app.
  4. To update later, drop the folder again on the same site.

Same place as the database: Firebase Hosting

  1. Install Node.js (LTS) from nodejs.org.
  2. Open a terminal in the K.Town folder and run:
npm install -g firebase-tools
firebase login
firebase use --add      (choose ktown-karongi)
firebase deploy

Your address is https://ktown-karongi.web.app. This also publishes firestore.rules for you.

8

First sign-in as the owner

  1. Open https://your-address/#/admin and sign in with the owner’s email and password.
  2. The first time, that account becomes the owner (admin) automatically.
  3. Press Set up menu to copy the K.Town menu, the 4 tables and the settings into the live database.
9

Add reception and kitchen

  1. Owner dashboard: Settings → Staff access. Add the reception and kitchen emails from step 4 with their role.
  2. Each person signs in once on their device. They stay signed in.
10

Print the QR codes

  1. Owner dashboard: Tables & QR. Type the web address (for example https://ktown-karongi.netlify.app) and press Save address.
  2. Press Print table cards. Print at 100% / actual size on thick paper or card, cut along the dashed lines, and put one in a stand on each table.
  3. Also print the poster (entrance, counter), the printed menu and some feedback cards.
  4. Scan each printed card with a phone before putting it out.
11

Set up the screens

WhoOpenTip
Kitchen…/#/kitchenA tablet or an old phone. Add to Home Screen, keep it charging, tap Start with sound. The screen stays awake.
Reception…/#/receptionLaptop, tablet or phone. Chimes for new orders, staff calls and bill requests.
Owner…/#/adminOn his phone: Add to Home Screen. Sales, reports, menu and feedback from anywhere.
12

Test with real phones

Scan Table 1, order a drink, watch reception and the kitchen, mark it ready, check the pay pop-up on the phone, send feedback, and see it on the owner’s phone. Then remove any test orders: owner dashboard, Orders, open the order, Cancel.

Need the offline demo again after going live? Add ?mode=demo to the address, for example …/index.html?mode=demo#/demo. Demo data stays in that browser and never touches the live database.

If something goes wrong

You seeFix
“The live database refused this change”The rules were not published, the owner email in the rules has a typo, or the staff email is not added under Settings → Staff access.
“This sign-in method is not turned on”Enable Anonymous and Email/Password (step 3).
“Email or password is not right”Check the user in Authentication → Users, or reset the password there.
“This account is not set up as staff”The owner adds that email under Settings → Staff access.
Guests see an empty menuSign in as owner and press Set up menu (step 8).
A QR code opens the wrong addressSet the web address in Tables & QR, then print again.
Phones still show an old version after an updateWhen you change files, change the version number (now 1.0.1) in index.html, sw.js and assets/js/app.js (for example to 1.0.2) before uploading.

Cost and privacy

Firebase’s free plan includes 1 GiB of storage, 50,000 reads and 20,000 writes per day. A busy day at K.Town uses a small part of this. Netlify’s free plan is enough for the menu. Neither asks for a card.

Guests’ phone numbers and emails are saved only when they tick “send me news”, and only the owner can see them. Message them only about K.Town, and delete anyone who asks. Rwanda’s personal data protection law (Law No. 058/2021) asks businesses to collect data with consent and keep it safe.
